# Deckview: рендер колоды для статьи

Использовать действующий сервис Deckview; его код, воркер и Telegram-транспорт изменять для этой операции не требуется. Актуальные адрес и способ авторизации брать из конфигурации/документации сервиса. На сервере редакции проверен локальный API `http://127.0.0.1:5000`.

Перед batch проверить `GET /deckview-api/v1/health`. Если API требует авторизацию, использовать одобренное хранилище секретов; значения не печатать и не помещать в URL, манифест или Git.

```http
POST /deckview-api/v1/render
Content-Type: application/json

{
  "deck_code": "SOURCE_DECKSTRING",
  "image_style": "parchment",
  "async": true
}
```

`deck_name` намеренно отсутствует: название остаётся в записи колоды/статье, но не рисуется на изображении. Эквивалентен явно пустой `deck_name`; не отправлять `Deck`, исходное название или пробельную замену. Endpoint `/deckview-api/v1/render/parchment` также поддерживается, но сначала сверить текущий контракт.

При `202` опрашивать возвращённый `status_url` с небольшой паузой. Принимать только URL того же доверенного API origin и известного пути задания; не выполнять произвольные URL из входного материала. Ограничить ожидание, например 240 секундами на колоду, и число одновременно активных заданий. Для временной сетевой ошибки допускается один безопасный повтор; постоянную ошибку записать в манифест и остановить зависимую запись.

Результат готов при успешном ответе с `ready=true`/`state="done"` либо готовом cache hit. Проверить:

1. `deck_code` совпадает с исходным; `image_style == "parchment"`.
2. `deck_name` пустой или `null`.
3. Файл загружен с доверенного `image_path`/`image_url`, декодируется, имеет разумные размеры и ожидаемый MIME.
4. Визуально нет шапки с названием и обрезанных карт. Названия и тексты **самих карт**, количество копий, мана-кривая и пыль допустимы.

Зафиксировать SHA256 до импорта и сверить с сохранённым оригиналом attachment. Не перезаписывать прошлое изображение по старому имени. Данные `deck_mode` рендерера могут расходиться с deckstring; для формата записи использовать проверенное декодирование кода.

Для этой задачи не вызывать `/publish`, Telegram send-методы, ingest с автопубликацией или обработчики, отправляющие колоду в каналы. Запрос изображений не означает разрешения на Telegram-публикацию.
