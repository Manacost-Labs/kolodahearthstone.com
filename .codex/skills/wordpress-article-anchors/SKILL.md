# Якоря, текстовые ссылки и кликабельные изображения

Делать переход понятным и рабочим: читатель видит назначение ссылки, попадает в нужный раздел или изображение и может повторить действие с клавиатуры и телефона.

## Выбрать нужное действие

- **Внутренний якорь:** элемент с уникальным `id` и ссылка `href="#этот-id"`.
- **Ссылка на другой материал:** обычный проверенный URL, при необходимости с существующим fragment.
- **Кликабельное изображение:** ссылка вокруг изображения, ведущая к разделу, странице, оригиналу или штатному lightbox.
- **Текст, открывающий колоду:** зарегистрированный редакторский shortcode, если нужен просмотр изображения/кода колоды, а не прокрутка страницы. Не заменять его самодельным JS.

Исходить из запроса и примера пользователя. Если направление перехода неоднозначно и меняет результат, уточнить только его. Не считать, что любое слово «якорь» означает оглавление, и не превращать обычную ссылку в всплывающее окно без причины.

## До правки

Прочитать правила текущего сайта. Получить конкретный post ID, текущие `post_content`, статус и доступную revision/резервную копию. Проверить редактор: Classic/TinyMCE или Gutenberg. Найти существующие `id`, `name`, `href`, shortcode и media attachment только в затронутом материале.

Составить короткое соответствие «видимая подпись → цель → id/URL → текст/изображение». При подготовке подборки использовать фактические разделы и их порядок. Не копировать навигационную сетку статьи-примера, если её ссылки повторяются или ведут к неверным классам.

## Поставить цель и ссылку

Для нового якоря выбрать короткий, осмысленный и стабильный ASCII kebab-case, например `mage`, `death-knight` или `deck-larva-combo-rogue`. Проверить уникальность во всём отрендеренном документе, включая тему и плагины. Суффикс добавлять только при реальной коллизии, одинаково во всех ссылках.

Цель ставить на видимый заголовок раздела, `figure` либо согласованный контейнер. Не менять существующие рабочие ID, на которые могут ссылаться извне. Сохранить исходные fragment и проверить их после редактирования. Имя атрибута `id` внутри `[hs_deck id="123"]` — ID записи, **не HTML-якорь**.

Для перехода внутри текущей статьи использовать `href="#mage"`: это сохраняет контекст черновика/preview. Для перехода на другую страницу использовать её канонический URL и реальный fragment. Не подставлять постоянную публичную ссылку вместо fragment в preview и не менять домен по аналогии с другим сайтом.

В Classic Editor менять только нужный узел HTML. В Gutenberg использовать Anchor/Link настройки блока или соответствующие block attributes, сохраняя согласованность сериализации. После сохранения повторно прочитать `post_content`: редактор мог удалить или изменить атрибуты.

## Текст и изображения

Применять подходящие [HTML-примеры](references/examples.md). Текст ссылки описывает цель: «Колоды Мага», «Открыть изображение колоды». Слова «здесь» и «картинка» без контекста не помогают выбрать переход.

У ссылки только с изображением должна быть доступная подпись через подходящий `alt` или `aria-label`. Если текст и картинка ведут к одной цели, по возможности объединить их в одну ссылку, а декоративному изображению дать пустой `alt`. Не вкладывать ссылки друг в друга.

Сохранять attachment ID, `src`, `srcset`, `sizes`, размеры, подпись, alignment, lazy loading и block/caption markup. Оборачивать именно изображение, не захватывая соседние ссылки и чужую подпись. Если оно уже внутри `<a>`, изменить существующую ссылку в пределах запроса. `<picture>` сохранять целиком.

Не подменять существующие lightbox-контракты простым href: сохранять необходимые классы и `data-*` зарегистрированного компонента. Для редакторского раскрытия колоды использовать существующий `[hs_deck_link]` выбранного сайта; проверить действующие атрибуты по реализации, включая `image_id` и код.

Не добавлять `target="_blank"` для перехода по этой странице. Для внешних ссылок открытие в новой вкладке применять только по запросу/редакционной конвенции; тогда добавить `rel="noopener"`. Не ставить `nofollow` всем источникам автоматически. URL и подписи экранировать по контексту; `javascript:` и произвольные event handlers не вставлять.

## Проверить результат

1. В сохранённом и отрендеренном HTML проверить уникальность ID, соответствие каждого локального fragment ровно одной цели, валидность вложения ссылок и доступное имя каждой image-only ссылки. Для поиска цели использовать `getElementById` с декодированным fragment, а не небезопасный CSS-селектор из входного текста.
2. В браузере кликнуть каждую новую ссылку: фактическая цель верна, адрес/fragment ожидаемый, нет лишнего открытия lightbox или перехода на публичный 404 из черновика. Проверить Back и загрузку страницы сразу с fragment.
3. Повторить Tab → Enter и убедиться в видимом focus. Проверить mobile: цель не спрятана под sticky header, ссылка нажимается, нет горизонтальной прокрутки. Использовать существующий scroll offset сайта; изменение глобального CSS или JS — отдельный scope.
4. Для ссылок на изображения проверить открытие правильного файла/lightbox и работу закрытия/копирования кода, когда эти действия предусмотрены. Не создавать production views, paid clicks или analytics события для теста.
5. Повторно сверить attachment/shortcode, статус и незатронутые части `post_content`. Сохранить черновик либо текущий запрошенный статус; правка якорей сама по себе не разрешает публикацию.

Сообщить, в какой статье добавлены какие переходы, и назвать конкретные непроверенные цели. Скриншот не заменяет проверку сохранённых ID и реального перехода.
